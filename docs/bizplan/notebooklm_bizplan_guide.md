# 用 NotebookLM 寫「AI 島 創業計劃書」— 操作指南

> 目的：把你**已有的真實素材**餵給 NotebookLM，讓它重組／擴寫／換角度，產出一份對外用的「創業計劃書」（投資人 / 創業競賽 / 加速器）。
> 核心心法：**NotebookLM 是「來源接地」的工具——它只根據你上傳的來源回答。** 餵得準，寫得準；不餵，它會膨風（腦補用戶數、把假設寫成現況）。
> 口徑鐵律：全書沿用 `docs/grant/repositioning.md` 的**誠實基線**（pre-launch / pre-revenue、註冊 17、活躍 ~4、營收 0、UGC 多為種子、禁用「閉環」當現況）。

---

## 〇、一句話流程

1. **開一個 Notebook** → 命名「AI 島 創業計劃書」。
2. **上傳來源**（下方第一節，你的專案裡都有）。
3. **先貼「系統設定提示詞」**（第二節）讓它記住角色 + 誠實護欄。
4. **一節一節下「主題提示詞」**（第三節）產出各章。
5. **用內建功能**（第四節）做語音導覽 / FAQ / 時間軸補強。
6. **照組裝順序**（第五節）拼成完整計劃書、人工覆核數字。

---

## 一、要上傳給 NotebookLM 的來源（Sources）

NotebookLM 免費版可放最多 **50 個來源 / 每來源約 50 萬字**；格式支援 **PDF / Google Docs / 純文字貼上 / 網址 / YouTube**。你的專案裡現成的好料：

### A. 一定要上傳（你的「地面真相」）
| 來源 | 檔案 / 位置 | 為什麼 |
|---|---|---|
| **完整補助計畫書** | `docs/grant/full-plan.md` | 最完整的產品/技術/商模/成本/競品底稿，直接當主幹 |
| **定位定錨（誠實口徑）** | `docs/grant/repositioning.md` | 逼 NotebookLM 守誠實基線的關鍵；**務必上傳** |
| **Pitch 骨架** | `docs/grant/pitch-deck.md` | 已濃縮的故事線、Q&A 彈藥、金句 |
| **產品章** | `docs/grant/ch3-product.md` | 三島功能模組細節 |
| **專案須知（產品現況）** | `CLAUDE.md` | 三島現況、技術棧、真實已上線功能 |
| **最新待辦/進度** | `docs/todo/todo_list_0715.md` | 讓它知道「已做 vs 規劃中」，別把 roadmap 當現況 |

> 做法：這些是 `.md`，NotebookLM 不吃 `.md` 副檔名時，**直接開檔全選複製 → 用「貼上文字（Paste text）」新增來源**即可；或先另存成 `.txt` / 匯出 PDF。

### B. 建議補充（讓市場/競品段落有外部依據）
- 外部市場報告（你 pitch 已引用的）：HolonIQ EdTech 市場規模、《Science》2019 MOOC 完課率、104 軟體職缺供需、資策會 MIC 世代 AI 使用率——**把原文/連結各自加成一個來源**，NotebookLM 才能「有來源地」引用，不會憑空生數字。
- 競品官網（Codecademy / Hahow / 六角學院等）網址各加一個來源，讓它做競品比較有依據。

### C. 不要上傳
- `.env.local`、任何金鑰、`docs/logerr.md`、`docs/note.md`（機密）。
- 內部吐槽 / 未定案的隨手筆記（會被它當事實引用）。

## 二、系統設定提示詞（**第一則就貼這個**，建立角色 + 誠實護欄）

> 複製整段貼進 NotebookLM 對話框當第一則訊息：

```
你是一位協助早期新創撰寫「創業計劃書」的顧問。我們要寫的是「AI 島（ai-island-web.snowrealm.pet）」的創業計劃書，讀者是投資人 / 創業競賽評審 / 加速器。

【只用來源】所有內容一律根據我上傳的來源。若來源沒有的數字或事實，明講「來源未提供，需補」，絕對不要自己編造用戶數、營收、完課率、市場規模、成長率。

【誠實基線／不可違反】以「repositioning」來源為準：
- 現況是 pre-launch、pre-revenue：註冊約 17、活躍約 4、營收 0、UGC 多為種子/AI 住民內容。
- 全文禁止把「求職閉環／商業閉環／創作變現閉環」寫成「已達成的現況」；正確講法是「產品路徑已串接、商業機制已建置、閉環假設待市場驗證」。
- KPI 一律先定義（分母是註冊/開始/完成哪一個、期間多長、使用者類型、招募來源與 CAC），再給數字；沒依據的數字標「需填」。
- 「AI 成本硬上限」不可寫成「商業模式成立的證據」——它只是保護機制，達上限會降級/停止。
- 單人創辦人寫成「執行力＋效率」優勢，同時說明補助/募資用於補內容審訂、AI 品質評測、資安、市場驗證等缺口。

【語氣】繁體中文、專業但不浮誇；一句結論先講，再給支撐；表格能講清楚就用表格。

先不要輸出整份計劃書。請你先閱讀所有來源，回我一份「本份創業計劃書的章節大綱（含每章要點與需要我補的真實數字清單）」。
```

它回大綱後，你再逐章叫它寫（第三節）。這樣品質最穩。

## 三、逐章「主題提示詞」（一次生成一章，逐段貼）

> 順序即建議的計劃書章節。每則都獨立、可直接複製。

### 1. 執行摘要（Executive Summary）
```
寫「執行摘要」，1 頁內。依序：一句話定位（用 repositioning 的兩島同一靈魂版本）、解決什麼問題、產品是什麼（三島：學習島/分身島/機會島＋創作者島）、目前階段（誠實：pre-launch/pre-revenue，數字照基線）、為什麼是現在、我們要的資源與要驗證什麼。結尾一句金句。凡無來源的數字標「需填」。
```

### 2. 問題與市場機會（Problem & Market）
```
寫「問題與市場機會」。用來源中的外部數據（MOOC 完課率、軟體人才供需、世代 AI 使用率、EdTech 市場規模），每個數字後面標註來源名稱；來源沒有的不要寫。分三層：市場夠大且成長、痛點（學不完/學不會/沒人即時幫）、AI 讓「學會用 AI＋寫程式」變剛需。最後做一張「痛點 → AI 島解法」對應表。
```

### 3. 產品與解決方案（Product）
```
寫「產品與解決方案」。用三島架構講：
- 學習島：章節/課程、AI 綠寶導師（分程度、引導式、跨對話記憶）、每日測驗、完課獎勵+證書、生涯路徑。
- 分身島（AI 員工/行動代理）：多模式（問答/寫程式/文件/簡報/試算表/設計雛形）、一鍵下載真檔 docx/pptx/xlsx、記憶、辦公室員工、省錢模式三檔、社群發布中心（AI 起草→人批准→發，強調對外動作紅線）、LINE/TG/Discord 橋接、桌面助手。
- 機會島：機會雷達（補助/獎學金/VC/徵件/標案/工作/實習/證照）、AI 作品分析→能力圖譜、PDF 規則解析。
- 創作者島 + 程式辭典（繁中白話，~1645 條 / 目標 5000）當支撐系統。
每島標清楚「已上線 vs 規劃中」（參考 CLAUDE.md 與 todo）。做一張「模組 × 成熟度（已上線/beta/規劃）」表。
```

### 4. 技術與差異化（Technology & Moat）
```
寫「技術架構與差異化」。重點：自建多供應商 LLM 閘道（容錯路由）、智慧路由+語意快取+成本記帳、RAG 綁自有教材、跨對話 AI 記憶、四語 i18n、PWA、Zeabur+GHCR 部署自動化。誠實說明：模型路由目前是「規則式關鍵字」非 ML、零成本多語是成本優化措施而非商業級 SLA。護城河寫成「整合組合 + 繁中在地 + 一套 AI 基建撐多產品線」，並註明「尚未形成市場護城河」。
```

### 5. 商業模式（Business Model）
```
寫「商業模式」。收入模式：Freemium（免費含 AI 導師）、Plus/Pro 訂閱（解鎖高階模型與工具）、Z 幣儲值、市集抽成、BYOK（自帶金鑰）、未來 B2B 機構授權。畫出價值主張→目標客群→收入來源的關係。單位經濟只寫「框架與待驗證假設」，不要宣稱已驗證。強調 Z 幣把重度使用者的 AI 邊際成本轉嫁的設計。
```

### 6. 成本結構與財務可行性（Financials）
```
寫「成本結構與財務可行性」。分項：LLM API（核心變動成本、有每供應商月上限）、Server（Zeabur，固定低）、Supabase、CDN、多語（零邊際）、人力（一人+AI，極低）。誠實說明「每 MAU 推理成本」目前缺真實用戶數據、正是要驗證的東西。所有金額標「需填實際數字」。做一張成本分項表。
```

### 7. 競品分析（Competition）
```
寫「競品分析」。逐一比較 Codecademy、Hahow、六角學院、ChatGPT 直接學等（依來源）。做一張比較表（維度：AI 導師/遊戲化/繁中在地/求職工具/UGC/多語/價格）。AI 島定位：整合組合 + 繁中在地 + 一套 AI 基建撐兩島。誠實列「潛在優勢但尚未形成護城河」。
```

### 8. 市場進入與成長（Go-to-Market）
```
寫「市場進入與獲客策略」。SEO/GEO（已對 AI 爬蟲開放）、推薦機制、遊戲化留存、社群 UGC 飛輪、LINE 推播觸達。誠實：目前尚未推廣。把「試辦 pilot」寫清楚：招募多少真實學習者、對照有無 AI 導師、要把哪一條學習路徑的完成率驗到多少（分母講清楚），別直接寫 30%。
```

### 9. 團隊與執行力（Team）
```
寫「團隊」。一人+AI 完成整個平台＝執行力與迭代速度的證明；同時說明募資/補助要補的專業缺口（內容審訂、AI 品質評測、資安、市場驗證、客服），並提「尋覓共同創辦人/顧問」。回答評審必問：誰審教材、誰做資安、生病怎麼辦。
```

### 10. 里程碑與募資訴求（Roadmap & The Ask）
```
寫「發展里程碑與資源訴求」。近 3–6 個月：試辦驗證完課率、建立 AI 品質評測基準、算出每 MAU 成本、驗證付費轉換。中期：三島功能補完（參考 todo_list_0715）、B2B。The Ask：要多少資源、用在哪三件事、能換到什麼可驗證成果。收尾金句：「產品我已經做完，我需要的是把它送到需要的人手上。」
```

### 11. 風險與對策（Risks）
```
寫「風險與因應」。至少涵蓋：AI 成本失控（上限+快取+分層）、單人團隊風險（找共創/顧問）、內容品質（待專家審訂）、獲客不如預期（多渠道+低 CAC 設計）、平台政策風險（多語免費端點、各社群平台 API）、資安/個資。每個風險配一句對策。做成風險矩陣表（機率 × 衝擊）。
```

## 四、善用 NotebookLM 內建功能（額外產出，拿來補強或做簡報）

- **Audio Overview（語音導覽 / 播客）**：一鍵把整份來源變兩人對談 podcast。可下 prompt 客製：「用 5 分鐘，向投資人講清楚 AI 島是什麼、目前階段誠實揭露、以及我們要驗證什麼。」→ 練 pitch、或當附件。
- **Briefing Doc（簡報摘要）**：自動生一頁重點摘要，適合當計劃書最前面的 one-pager。
- **FAQ**：自動生常見問答——直接對應 pitch-deck 的「Q&A 預備彈藥」，補齊評審會問的問題。
- **Timeline（時間軸）**：把產品開發歷程 + 未來里程碑排成時間軸，放進「里程碑」章很有用。
- **Study Guide**：對你自己有用——快速自我複習整份計劃書邏輯，上台前用。

## 五、組裝順序與最後把關

1. 先讓它出**大綱**（系統提示詞那步）→ 你確認章節與「需補數字清單」。
2. **逐章生成**（第三節）→ 每章生成後貼回你自己的文件。
3. **把所有「需填 / 需補」的數字換成真實值**（用量、成本、pilot 目標、CAC…）。這步 NotebookLM 幫不了你，只有你有真數據。
4. **誠實口徑複查**：全文搜尋「閉環」「已達成」「30%」等字，確認沒有把假設寫成現況（對照 repositioning）。
5. 用 **Briefing Doc** 生 one-pager 放最前、**FAQ** 放附錄、**Audio Overview** 當 pitch 練習。
6. 定稿前跑一次：數字有沒有來源、KPI 有沒有定義、風險有沒有對策、The Ask 是否明確。

## 六、常見雷（NotebookLM 特性）

- **它會膨風**：沒有系統提示詞的護欄，它很容易生出「數千用戶 / 30% 完課 / 已獲利」。→ 一定先貼第二節那則。
- **它只認來源**：外部市場數字若沒上傳成來源，它可能拒答或含糊。→ 把市場報告各加成一個來源。
- **一次一章最穩**：叫它「一次寫完整份」品質會掉、會略過細節。→ 逐章下提示詞。
- **它不會算你的財務**：成本/單位經濟要你給真實數字，它只負責排版與論述。
- **語言**：全程用繁體中文對話，輸出才會穩定繁中。
