## ① 一句話定位（改掉「求職型程式補習班」的味道）

> **AI 島是一套 AI 陪伴式的「學習 × 創作」系統：用學習脈絡理解與分程度回應，降低初學者從「不敢開始」到「能獨立解題」的門檻；並透過創作者島嶼，讓一般人也能用 AI 把想法變成作品 —— 共同降低 AI 時代對「學」與「做」的恐懼。**

**兩座島、同一個靈魂：把「可怕、不敢碰」變成「敢動手、做得出來」。**
- 🏝️ **學習島**：降低對「寫程式」的恐懼 —— 不敢開始 → 能獨立解題。
- 🎨 **創作島（Creator Island）**：降低對「用 AI 創作」的恐懼 —— 想法在腦中 → 做成作品、分享。

**求職 / 證書 / LeetCode / 就業力＝後段結果，不是品牌主軸。** 筆記、社群、部落格、市集、多語、島嶼＝支撐系統，各司其職、不搶 C 位。（批評稿：現在的報告像 18 個角色一起站 C 位、評審不知道該看誰。）

## ② 本次補助研發題目（不是「已有幾個模型/表/API」，是「要解什麼」）

工程量（6 供應商 LLM 閘道 / RAG / SSE / 向量庫 / 392 API）證明**執行力**，但那是「已完成的基礎建設」，不是補助要解的**研發題目**。本計畫要研發、且可量測進步的核心是三件事：

### （一）AI 教學／陪伴品質（學習島導師 + 創作島綠寶共題）
不是「一般問答準確率」，而是：
- **問題意圖辨識**：能不能辨識使用者「真正卡住的概念」（而非表面字句）。
- **程度判斷 + 分層解釋**：能不能依使用者程度調整解釋深度、不一次丟太多答案。
- **引導式回答 + 理解確認**：能不能用引導取代直接給答案、並確認對方真的懂了。
- **長期學習記憶**：能不能依學習歷程連續教學。
- 創作端：綠寶能不能接住當下靈感/卡點、給「可立刻動手」而非空泛的方向。
- **可量測目標**：建立「正確性 / 可理解性 / 教學性」三軸評測集與人工標註基準；補助後導師回答在此評測集的達標率從**目前無系統評測**→**建立基準並提升**。

### （二）AI 成本與品質平衡
- **模型路由 / 語意快取 / 配額 / Token 最佳化 / 高成本問題升級 / 每位使用者成本追蹤**。
- 兩座島共用同一套 AI 基建（優勢：一套撐兩條產品線）。
- **可量測目標**：建立「每位活躍使用者（MAU）推理成本」模型、快取命中率、與「品質 vs 成本」的取捨曲線。

### （三）真實市場驗證
- 學習島：完課 / 留存 / AI 滿意度 / 付費意願。
- 創作島：創作完成率 / 作品產出 / 自然 UGC 與市集自然交易。

> 一句話研發題目：**「補助後，AI 導師 / 創作夥伴會從『可用但品質未系統評測、成本未量化、閉環未驗證』的狀態，進化到『有評測基準、有每-MAU 成本模型、有真實 pilot 驗證』的可量測狀態。」**

## ③ 補助前後差異表（比 392 支 API 還重要的一張表）

評審不是來看你做了多少，而是看「給你錢後，會新增什麼公共價值與可驗證成果」。

| 項目 | 現況（誠實） | 補助後（可驗證成果） |
|---|---|---|
| AI 回答品質 | 可用，但**無系統性評測** | 建立正確性／可理解性／教學性評測集與基準、並提升達標率 |
| 模型策略 | **規則式**關鍵字路由（非 ML） | 依題型 / 難度 / 成本的動態選擇 + 快取，量測命中率與成本 |
| API 成本 | 小規模、後台記帳自 2026-06-29 起才完整 | 建立**每 MAU 成本**與配額模型、驗證品質×成本×付費意願關係 |
| 教材 | **AI 輔助生成、待人工校訂**（非專家審訂） | 專家校訂與品質標準（委外項目，見 ch8） |
| 使用者 | 註冊 **17**、活躍 ~4 | 完成真實 pilot（見 ④ 定義） |
| 商業 | 機制/金流已建置、**營收 0** | 驗證付費轉換與單位經濟（非宣稱已閉環） |
| 社群 / UGC | 多為 **seed / AI 住民** 內容 | 啟動自然 UGC 飛輪 |
| 創作島變現 | 路徑已串接、市集**無自然交易**、提領人工 | 驗證創作 → 分享 → 變現的市場循環（假設待驗證） |
| 兒童 / 低年齡 | 願景 | 列為**後續研究路線、不混入本期**（避免超載承諾） |

> ⚠️ 全書禁用「完整閉環 / 求職閉環 / 商業閉環 / 創作變現閉環」當**現況**。正確口徑：「產品路徑已串接、商業機制已建置、**閉環假設待市場驗證**」。（批評稿：管子都接好就宣布水力發電廠營運，管子很多但渦輪還沒轉。）

## ④ KPI 與 API 成本驗證邏輯（把「AI 填的夢想數字」換成可辯護的設計）

### KPI 先定義、再給數字（沒定義的 30% 是煙霧彈）
每個 KPI 必須明確標註，且**不拿 MOOC 3.13%（完整大型課程完課率）硬比 AI 島（短章節完成）**——分母不同、不可直接比較：

- **學習路徑**：完成哪一條（如「Python 入門 15 節」）、而非泛稱「完課」。
- **期間**：多長時間內（如 4 週）。
- **分母**：註冊 / 開始第一節 / 完成第一節 —— 明講是哪一個。
- **使用者類型**：新手 / 進階、免費 / 付費。
- **招募來源與量**：從哪來、CAC、註冊轉換率、產品每月可承載量。

pilot 設計（試辦）也要據此定義，而非先寫「14,000 註冊 / 4,000 MAU / 30% 完課」等未從預算/CAC/轉換率推導的數字。

### API 成本驗證邏輯（回應林董最擔心的「成本沒真正抓到」）
不要寫「固定成本低 / 硬上限 / 可安全規模化」——**「硬上限」的真相是達上限後服務停止或降級，不是商業模式成立的證據**。正確論述：

> 本計畫將**驗證 AI 導師/創作夥伴品質、每位活躍用戶（MAU）推理成本、與付費意願三者之關係**，建立可持續的**模型路由、配額與快取策略**。

支撐這條的既有工程（可寫、屬實）：多供應商容錯路由、語意快取（省重複問答 token）、分層授權（高階模型只給付費/特權）、每次呼叫成本記帳（`ai_model_usage`）、Z 幣續用把邊際成本轉嫁重度使用者。**目前缺的是真實用戶數據**去算出每-MAU 成本 —— 這正是補助要買的東西。

### 「零成本多語」降級（別當核心護城河）
非官方 Google 免費翻譯端點有穩定性 / 政策 / 商業使用風險、且無人工校訂。定位為**成本優化措施 / 國際化輔助 / 現階段原型機制**，**不寫成「四大核心創新」之一**。（有程式碼哨兵保護 + hash 快取 + 每 3h cron，可寫；但別暗示商業級 SLA。）

### 單人創辦人：把「優勢」寫成「補助必要性」
「一個人 + AI 完成一般團隊產品」證明**執行力與效率**，但不等於未來仍應一人做完。正確敘事：

> 創辦人已用 AI 驗證高效率開發能力；**補助將用於補足內容審訂、AI 品質評測、資安與市場驗證等單人無法長期承擔的專業缺口**。

這樣「補助的必要性」才成立（也回答評審必問的：誰審教材 / 誰做資安 / 誰做客服 / 生病怎麼辦 / 392 API 誰維護）。
