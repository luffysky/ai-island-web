# 分身島規劃待閱 — 四個大工程的想法與計劃書

> 作者：Claude（長期在 AI 島 repo 幹活的這隻）· 2026-08-01
> 對象：林董。這份是**規劃、不是已完成**——把四個「不是純程式小工、要先想清楚方向」的大工程攤開講。
> 背景：分身島的**純程式引擎層本輪已補完**（2.1.3-2.1.6 引擎、2.6.1/2.6.2/2.6.5 員工、2.7.1/2.7.3/2.7.4/2.7.12/2.7.13 省 token 治理）。
> 剩下這四個是**「產品化 / 世界觀 / 生態」層**，要的是產品決策，不只是寫 code。每個都給：願景 → 資料/架構 → 分期 → 誠實評估。

---

## 現況盤點：這四個站在什麼地基上

本輪做完後，分身島已有的「零件」（規劃這四個都靠它們，不用重造）：
- **員工＝技能** `agent_skills`（名稱/職務/職能 prompt/工具集/max_steps/**daily_budget**）
- **排程 + 自主** `agent_schedules`（**autonomous** 模式：員工自己決定做什麼＝2.6.1）
- **成效統計**：`agent_tasks`（每任務 skill_id/status/step_count/cost_usd）→ 已能算 used/成功率/平均步數；`/me/ai-usage` 有成本圖
- **技能自動蒸餾** 2.1.3（做完一次→存成員工）＋**經理-專才階層** 2.1.4＋**共享資料黑板** 2.6.5
- **動態工具來源**：MCP（`agent_mcp_servers`）＋ **OpenAPI**（`agent_openapi_sources`）2.1.6
- **產出匯出**：AgentClient 已能把結果匯出 docx/pptx/xlsx

→ 重點：**這四個大工程有一半是「把現有資料換個框架呈現 + 加一層編排」**，不是綠地。下面每個會標「哪些現成、哪些真的要新建」。

## 一、2.6.4 AI 公司世界觀（能力向量 / 招募 / 培訓 / KPI）

### 願景
把「一堆 agent 技能」重新框成 **「你在經營一間 AI 公司」**：每位員工有專長、你招募他、訓練他、看他的 KPI。這是**管理層的遊戲化外皮**，把冷冰冰的工具變成「帶團隊」的爽感——這是留存與情感黏著的關鍵。

### 資料 / 架構（大半現成）
| 元素 | 怎麼做 | 現成？ |
|---|---|---|
**員工檔案卡** | `agent_skills` 既有 + 加 `capability_tags jsonb`（研究/寫作/程式/溝通/設計…）| 表現成、加 1 欄 |
**能力向量** | 由 allowed_tools + 歷史成功率 + goal_template 推導（可先規則式、之後 embedding）| 資料現成、算法要寫 |
**KPI 儀表** | 從 `agent_tasks` 聚合：完成數/成功率/平均步數/花費/最近產出 | **幾乎全現成**（`/api/agent/kpi` 已有雛形）|
**招募** | 從「職缺角色」一鍵生員工（複用 2.1.3 蒸餾 + 技能模板）；或市集招募（接 §四）| 蒸餾現成 |
**培訓** | 對員工「回饋 → 改職能/加工具」；把它跑過的好任務吸收成更強職能 | 編輯現成、吸收要寫 |

### 分期
- **MVP（2-3 天）**：員工檔案卡（emoji/職務/**能力標籤**/KPI）＋「組織總覽」頁（你的 AI 團隊一覽 + 各員工 KPI）＋招募＝現有「建員工」換成「面試/錄取」文案。**幾乎全靠現有資料換皮 + 一欄 capability_tags。**
- **v2**：能力向量視覺化（雷達圖）、培訓閉環（回饋→自動優化職能）、員工升級/等級（用 usage 當經驗值）。
- **v3**：員工間協作編組（接 2.1.4 經理-專才 + 2.7.7 COO）。

### 誠實評估
**CP 值最高的一個**——大半是現有資料換框架，情感/留存回報大。⚠️ 純外皮小心變空殼：能力向量要**真的反映**員工能耐（別亂給星等）。**建議先做這個**，它也是 §三 COO、§四 市集的世界觀基礎。

## 二、2.6.6 Workspace Hub（簡報 / 表格 / 文件生成器聚合入口）

### 願景
一個地方，把「分身產出的東西 + 你自己的創作」都變成**可管理、可再編輯的文件**：文件、簡報、表格。像 Genspark 的 workspace / 迷你 Google Workspace。

### 誠實評估：**這是四個裡最大的一個、也最該「切開來」做**
- **在瀏覽器裡做出堪用的簡報編輯器 / 試算表編輯器 ＝ 各自是一個獨立產品級工程**（拖拉、公式、版面…）。硬做會吞掉好幾週、還做不贏專業工具。**不建議自己蓋 slides/sheets 編輯器。**
- 但「聚合入口」本身很有價值、而且**大半現成**：分身能匯出 docx/pptx/xlsx、有 BlogEditor(TipTap) 能編文件、筆記/部落格/創作島都有內容。

### 分期（務實切法）
- **MVP（3-4 天）＝「產出中心」**：一張表 `workspace_documents`(id/user/type/title/content/source_task/updated_at) 把「分身任務結果、筆記、部落格草稿、匯出檔」**收攏成一個列表**：開得起來、文件類用現有 TipTap 再編、簡報/表格類提供「重新生成 / 下載 / 用外部工具開」。**先解決「東西散在各處」的痛，不碰編輯器工程。**
- **v2**：文件類全上 TipTap 協作編輯（`@snowrealm/rich-editor` 已在 Space 抽成套件，可複用）；簡報用「Markdown → 投影片」（複用 MD2Deck 的思路，零編輯器、純轉換）。
- **v3**（要才做）：輕量表格（唯讀資料表 + 篩選排序，不做公式）；真・slides 編輯器＝獨立立項或接第三方。

### 依賴 / 建議
先做 MVP 產出中心（高 CP）、**明確不自建 slides/sheets 編輯器**。簡報走「MD→deck」轉換路線最聰明。這個可**晚於 §一**。

## 三、2.7.7 AI COO（AI 營運長）

### 願景
一個**站在所有員工之上的管理 agent**：它看你的目標、待辦、機會、以及你的 AI 團隊，**決定今天誰該做什麼、審員工的產出、控預算、每天給你一份營運報告**。從「你一個個下指令」升級成「你只跟 COO 講方向，它調度整間公司」。

### 架構（站在 2.6.1 + 2.1.4 肩上）
COO ＝ **組織層的自主規劃器**（2.6.1 是單一員工版、COO 是全公司版）：
1. **蒐集**：你的目標/pending 批准/機會島截止/各員工職責與近期產出（＋共享黑板 2.6.5）。
2. **規劃**：LLM 產出「今日工作分配」——哪位員工做哪件事（複用 `planAutonomousGoal` 的骨架、放大到多員工）。
3. **調度**：對每項 → `launchAgentTask(skillId=該員工)`；對外/破壞性動作仍走 `awaiting_approval`（紅線不破）。
4. **審核**：員工做完，COO 讀結果、給你**一份彙整營運報告**（接每日晨報 §5 / daily-brief）。
5. **控管**：尊重每位員工的 `daily_budget`(2.7.4) + 全域上限，COO 不能繞過。

### 資料
`agent_coo_runs`(id/user/date/plan jsonb/report/status)；其餘全複用。

### 分期
- **MVP（3-4 天）**：手動「讓 COO 規劃今天」按鈕 → 產出分配計畫（先只**提案、不自動跑**，你一鍵核准才派）→ 跑完給營運報告。
- **v2**：排程每日自動 COO run（複用 cron）；預算/優先序最佳化；COO 會依上次成效調整分配。
- **v3**：多層（COO→經理→專才，接 2.1.4）。

### 誠實評估
**最有「哇」感、但成本與風險最高**（一個 agent 指揮一群 agent＝可能連環燒 token / 連環對外）。**紅線**：COO 只到「提案 + 經核准調度」，對外一律逐項批准；預算硬上限一定要有（已有 daily_budget/STEP_CAP 可接）。**建議排在 §一 之後**（要先有「員工/組織」世界觀，COO 才有東西可管）。

## 四、2.7.9 MCP 市集 + 技能市集分享

### 願景
使用者把自己調教好的**員工（技能）**、以及**工具來源（MCP / OpenAPI）**分享出來，別人一鍵招募/安裝。社群 + 網路效應層——好員工被複製、創作者有成就感。

### 拆兩塊（安全性差很多、要分開）
| 分享什麼 | 帶什麼 | 風險 | 做法 |
|---|---|---|---|
**技能（員工）** | 職能 prompt + 工具集（都是站內既有安全工具）| **低** | 可開放使用者發布 |
**MCP / OpenAPI 來源** | **外部 URL** | **高**（SSRF/惡意端點/釣憑證）| **只收錄審核過的、或站方 curated**，不開放任意 URL 上架 |

### 資料 / 架構（技能分享大半現成）
- `agent_skills` 加 `is_public bool` + `published_at` + `install_count`；`agent_skill_installs` **已存在**（內建安裝就是這套）→ 市集安裝＝把 public 技能複製一份到使用者名下。
- 市集頁 `/agent/market`：瀏覽/搜尋/分類/熱門（複用 2.7.12 排序）、預覽職能與工具、一鍵招募。
- **審核**：發布進 pending → 後台 review（複用機會島/貼文的 moderation 模式）→ 上架。防惡意 prompt（越權/釣魚指令）。

### 分期
- **MVP（3-4 天）**：技能發布/審核/市集瀏覽/一鍵招募（**只技能、不含外部工具來源**）。
- **v2**：評分/評論、作者頁、被招募數排行、Z 幣打賞（接經濟系統）。
- **v3**：curated 工具來源市集（站方審核的 MCP/OpenAPI）、創作者分潤。

### 誠實評估
**技能分享安全又有網路效應、值得做**；**外部工具來源分享是地雷**（別開放任意 URL）。此案**依賴 §一**（員工世界觀）才有「員工可分享」的語意，排在 §一 之後、可與 §三 並行。

## 綜合建議：優先序、依賴、路線

### 依賴關係
```
2.6.4 AI 公司世界觀（地基：員工/組織/KPI）
   ├─→ 2.7.7 AI COO（管理這間公司）
   └─→ 2.7.9 技能市集（分享這些員工）
2.6.6 Workspace Hub（獨立、與上面平行；但別自建 slides/sheets 編輯器）
```

### 我的排序（CP 值 × 依賴）
1. **先做 2.6.4 AI 公司世界觀 MVP**——最便宜（大半現有資料換框架）、回報最大（留存/情感）、又是另兩個的地基。
2. **接 2.7.9 技能市集 MVP（只技能）**——安全、有網路效應、依賴 §一。
3. **再 2.7.7 AI COO MVP（提案制、不自動跑）**——最有哇感但成本/風險高，要先有組織可管。
4. **2.6.6 Workspace Hub** 獨立進行，**只做「產出中心」聚合、簡報走 MD→deck、明確不自建編輯器**。

### 三條不可破的紅線（四個都適用）
- **對外/破壞性動作永遠逐項批准**（COO/自主/市集招募來的員工都一樣）。
- **預算硬上限**（daily_budget + STEP_CAP）任何編排都不能繞過——防連環燒錢。
- **外部 URL（MCP/OpenAPI 來源）不開放任意上架**，只走站方 curated + 審核。

### 每個 MVP 的驗收
- 2.6.4：能在「組織總覽」看到你的 AI 團隊 + 每位真實 KPI，能招募/訓練一位。
- 2.7.7：按「COO 規劃今天」拿到一份分配提案，核准後員工真的分頭去做、回來一份營運報告。
- 2.7.9：把自己一位員工發布、審核上架、用另一個帳號招募回來能用。
- 2.6.6：分身的產出 + 你的筆記/部落格都在一個 hub 列得出來、文件類能再編。

> 一句話：**先把「AI 公司」的世界觀與地基（2.6.4）做起來，COO 與市集才有意義；Workspace 獨立做、但聰明地不重造輪子。** 每個都從「提案/唯讀/聚合」的安全版起步，驗證了再放權。
