# 第九章　關鍵績效指標（KPI）

> 依 spec 要求「全部量化」。目標值以 `[目標:待確認]` 標示，供申請人依補助規模與企圖心定案；基準值取自 2026-07 資料庫實查（詳 `tech-inventory.md`）。撰寫原則：每項 KPI 皆可量測、有明確定義與資料來源。

## 9.1 KPI 設計原則

- **可量測**：每項指標皆有明確定義與系統資料來源（本平台已具自有行為分析與金流資料，第六章）。
- **對應補助範疇**：涵蓋「AI 核心數位服務」之技術指標、市場落地之用戶與營收指標、以及服務品質指標。
- **分年遞進**：設 Y1 / Y2 目標，並標示現況基準。

> 關鍵論述與達成路徑：以完課率作為旗艦 KPI（對應市場痛點）。
> ⚠️ **口徑（見 `repositioning.md` ④）**：完課率**先定義分母/期間/路徑/使用者類型**（分母＝註冊／開始／完成第一節，明講哪一個），再給數字；且 **AI 島的「完成短章節」與 MOOC 的「完成完整大型課程」分母不同、不可直接把 30% 對比 3.13%**——MOOC 3.13% 只作為「線上學習完課難」的背景引用，非直接對標基準。真正痛點更貼近「新手不知從哪開始、看不懂錯誤、通用 AI 太技術、vibe coding 沒底層能力」（見 ch2）。
> - **基準**：現況完課證書 0、`lesson_progress` 11，須先於試辦（ch2.5）建立本產品之完課率基準。
> - **達成路徑（試辦 pilot）**：招募 N 名真實用戶 → 設有 / 無 AI 導師與遊戲化之對照 → 按季量測完課率、留存、AI 互動 → 驗證「AI + 遊戲化 + 社群提升完課率」之假設。
> - **證書數以漏斗反推**（非憑空設例）：`註冊 × 開始課程率 × 完課率 = 證書數`；例值須待各轉換率之試辦數據校準，目前僅為示意。

## 9.7 營運漏斗（可審查的成長閉環）

回應「17 人現況 → 補助 → 規模化」之可驗證路徑，以單一漏斗貫穿獲客到營收（各轉換率待試辦校準）：

```mermaid
flowchart LR
    A["曝光/獲客<br/>廣告+SEO/GEO+推薦"] --> B["註冊<br/>17 → 目標成長"]
    B --> C["啟用: 開始第一課"]
    C --> D["活躍: 真人MAU<br/>(排除bot/seed)"]
    D --> E["AI互動 + 遊戲化留存"]
    E --> F["完課 + 發證"]
    F --> G["付費轉換<br/>訂閱/Z幣/市集"]
    G --> H["營收 → 部分自籌 + 再投入"]
```

| 漏斗環節 | 現況 | 資料來源 | Y1 目標 |
|---|---|---|---|
| 註冊 | 17 | `profiles` | `[目標:待確認]` |
| 啟用（開始課程） | 極低 | `lesson_progress` | `[目標:待確認]` 轉換率 |
| 真人活躍 MAU | 約 4 | 真人 session | `[目標:待確認]` |
| 完課發證 | 0 | `certificates` | `[目標:待確認]` |
| 付費 | 0 | `orders`/`subscriptions` | `[目標:待確認]` |

> 此漏斗使經費用途（第八章：獲客、研發、內容校訂）與 KPI 一一對應，形成可審查之閉環。

> **Y1 / Y2 用戶目標之反推方法（避免憑空設值）**：目標用戶數不應直接填「3,000」，而應由**第八章推廣預算反推**——`可獲客數 = 推廣預算 ÷ CAC`。惟現況 CAC 未知（pre-launch），故：(1) 先於試辦（第二章 2.5）取得早期 CAC 與各環節轉換率；(2) 再以「推廣費 ÷ 試辦 CAC × 轉換率鏈」推導 Y1 註冊 / 活躍 / 完課 / 付費目標。**在 CAC 校準前，本章例值（3,000 / 1,000…）僅為規模示意、非承諾值**，正式版須待經費定案與試辦數據後填實。

> **完課率之早期里程碑（分段達成）**：現況 lesson_progress 11、證書 0，直接跳 ≥30% 缺中間點。里程碑設計：**試辦首 cohort 完課率 ≥ 20% → 第 2 cohort（優化後）≥ 25% → Y1 末穩定 ≥ 30% → Y2 ≥ 40%**，每季以 cohort 數據驗收。

## 9.8 KPI 反推試算（示範模型，假設全數攤開）

> 本節將 Y1/Y2 目標由**推廣預算 ÷ 每註冊成本（CPR）× 漏斗轉換率**逐層推導，取代憑空設值。所有假設標 `[假設]`，須以第二章 2.5 試辦（pilot）數據校準；預算為 `[需確認]`。

**輸入假設**

| 參數 | Y1 | Y2 | 說明 |
|---|---|---|---|
| 行銷預算（NT$） | 60 萬 `[需確認]` | 120 萬 `[需確認]` | 0 資金者初期來自競賽 / 小額 / 早期營收 / 貸款，Y2 隨驗證放大 |
| 每註冊成本 CPR | NT$150 `[假設]` | NT$120 `[假設]` | 混合付費 + 自然流量；Y2 因品牌 / SEO 改善而下降 |
| 註冊→啟用（開始首課） | 50% `[假設]` | 55% `[假設]` | 產品體驗改善 |
| 啟用→完課率（旗艦） | 25%→30% `[假設]` | 40% `[假設]` | 對照 MOOC 3.13%；分段里程碑 |
| 免費→付費轉換 | 3% `[假設]` | 5% `[假設]` | Freemium 典型 2–5% |
| 付費 ARPU（年，NT$） | 1,500 `[假設]` | 1,500 `[假設]` | 分層訂閱（Plus 1,490/年、Pro 2,990/年）+ Z 幣混合、計入月繳churn之混合值 |

**推導結果**

| 指標 | Y1 | Y2（累積） | 計算 |
|---|---|---|---|
| 新增註冊 | ≈ 4,000 | +10,000 → 累積 ≈ 14,000 | 預算 ÷ CPR |
| 啟用（開始課程） | ≈ 2,000 | ≈ 7,700/年 | 註冊 × 啟用率 |
| 完課發證 | ≈ 500 | ≈ 3,000 | 啟用 × 完課率（分段爬升） |
| 付費用戶 | ≈ 120 | ≈ 700 | 註冊 × 轉換率 |
| 年營收（NT$） | ≈ 18 萬 | ≈ 105 萬 | 付費 × ARPU（1,500） |

**兩點誠實結論**：
1. **目標值是算出來的、不是喊的**：改任一假設（預算 / CPR / 轉換率），下游 KPI 隨之連動，評審可審查邏輯。
2. **單靠補助期兩年，營收（Y2 ≈ 105 萬）尚不足以完全自立**——這正說明補助之必要（買時間驗證單位經濟），也提醒 ARPU / 轉換率須靠 pilot 儘早拉高。

> ⚠️ 0 資金前提：上表 Y1 行銷 60 萬本身需有來源。若初期僅能投入 `[需確認]` 例如 20–30 萬（競賽獎金 / bootstrap），則按比例縮小 Y1 目標（註冊約 1,300–2,000），Y2 再隨資金到位放大——模型同一套、只換預算輸入。

## 本章小結

本計畫 KPI 以**「完課率」為旗艦指標**（直接對標市場痛點），輔以用戶成長、商業轉換、AI 技術與服務品質等面向，全部可由平台自有資料量測。所有目標值待申請人依補助規模定案，惟指標體系已完整、可稽核，並與補助之「AI 核心數位服務」範疇緊密對應。

> 備註：現況基準之偏低（用戶 17、營收 0）為 pre-launch 事實，本計畫之目的即在補助挹注下達成上述成長——KPI 之落差正說明補助之必要性與加值空間。
