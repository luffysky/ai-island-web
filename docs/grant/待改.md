我不滿意的地方
一、AI 島被寫成「求職型程式教育平台」了

這是我認為最大的偏差。

目前核心定位寫成：

「AI 導師為核心、遊戲化驅動、繁體中文原生，學習 → 陪練 → 產出 → 社群 → 求職 / 變現。」

這句看起來很完整，但不夠像你真正想做的 AI 島。

你真正一直講的是：

降低人對程式的恐懼
降低人對 AI 的恐懼
讓不知道怎麼開始的人能開始
讓沒有動力的人願意繼續
讓 AI 時代的學習年齡提前
讓家長能先體驗，再理解孩子為什麼可以更早學
AI 導師要能看懂使用者到底卡在哪
不只是「回答正確」，而是用對方聽得懂的方式回答

但這份報告現在一直往：

軟體人才缺口
求職閉環
證書
履歷
LeetCode
就業力

靠攏。

這會讓 AI 島看起來像：

「另一個 AI 化的程式補習平台。」

而不是：

「重新設計 AI 時代的程式學習入口。」

求職可以是後段結果，但不該是品牌主軸。

二、真正的核心研發問題沒有被寫清楚

現在技術章花大量篇幅寫：

幾家模型
幾張表
幾支 API
有 RAG
有 SSE
有向量資料庫

這些能證明工程量，卻不等於補助計畫的「研發題目」。

評審可能會問：

你都有了，那你還要研發什麼？

目前計畫書說的是「深化 AI 核心服務、擴大用戶」，太模糊。

你真正需要補助解決的核心，應該是：

AI 導師的教學準確性

不是普通問答準確率，而是：

能不能辨識使用者真正卡住的概念
能不能依程度調整解釋方式
能不能避免一次丟太多答案
能不能確認使用者真的理解
能不能根據學習歷程連續教學
能不能在品質與 API 成本之間取得平衡

這才是你的核心研發。

現在文件寫了很多「已有什麼」，卻沒有集中回答：

補助後，AI 導師會從現在的什麼狀態，進化到什麼可量測狀態？

三、「完整閉環」出現太多次，而且太早

文件一直使用：

完整閉環
求職閉環
商業閉環
創作變現閉環

但目前：

營收是 0
訂閱是 0
付費訂單是 0
證書是 0
真實 UGC 極少
市集尚未有自然交易
提領仍是人工流程

這時候稱「完整閉環」，評審很容易反問：

閉在哪裡？你只完成了流程連線，還沒有完成市場循環。

比較準確的說法應該是：

產品路徑已串接
商業機制已建置
閉環假設待市場驗證
已完成學習、內容與社群模組整合

現在的寫法有點像把水管都接好，就宣布水力發電廠正式營運。管子確實很多，但渦輪還沒轉。🌪️

四、API 成本問題被寫得太樂觀

這是你剛才最擔心的問題，但文件反而寫：

固定成本低
變動成本具硬性上限
可安全推廣
不致因流量突增而成本失控
多語零邊際成本

這裡我很不滿意。

因為「硬上限」的真相是：

錢不會繼續爆，但服務會停止或降級。

誠實口徑裡自己也有寫，達上限的代價是服務不可用。

所以不能把它寫成「可安全規模化」。

你目前真正的狀況是：

你和 Nami 兩人每月就可能消耗上千元
使用者若重度使用，成本可能高度偏斜
高品質模型直接影響產品核心體驗
便宜模型可能降低導師品質
目前尚未有足夠真實用戶數據，無法估算每 MAU 成本
成本上限是保命機制，不是商業模式成立證據

更好的寫法應該是：

本計畫將驗證 AI 導師品質、每位活躍用戶推理成本與付費意願之關係，建立可持續的模型路由、配額及快取策略。

而不是先宣布：

成本可控、可以規模化。

現在還不能證明。

五、「零成本多語」應該降級，不該當核心創新

非官方 Google 免費翻譯端點：

有穩定性風險
有政策變動風險
有商業使用風險
沒人工校訂
技術門檻也不算主要護城河

文件自己已經承認這些問題，但又把它放在「四大核心創新」第二項。

這會讓評審抓到一個很容易攻擊的點：

你的核心創新依賴非官方免費服務？

這不划算。

它可以當：

成本優化措施
國際化輔助能力
現階段原型機制

但不要當核心護城河。

六、用 MOOC 3.13% 當主要敵人，有點打錯人

這份報告非常依賴《Science》2019 的 MOOC 完課率。

數據本身可以引用，但推論現在跳太快：

MOOC 完課低
原因是缺即時協助、動機、社群
AI 島有這些
所以有望提升完課

問題是，該研究證明完課率低，不一定直接證明你的四個原因就是主要因果。

文件後面有補「間接推論」，算有煞車，但前面摘要仍然寫得很肯定。

而且 AI 島的真正敵人不只 MOOC。

更直接的痛點應該是：

新手不知道從哪開始
不懂錯誤訊息
通用 AI 回答太多、太快、太技術
Vibe coding 帶來第一次成功，卻沒有底層能力
使用者會做出東西，但不知道架構、安全、維護風險
現有課程與 AI 聊天彼此分離

這些比「MOOC 完課率 3.13%」更貼近 AI 島。

MOOC 數據可以留下，但不該獨霸舞台。

這會被懂研究設計的評審打穿。

完成哪一條學習路徑

沒有定義，30% 是煙霧彈。

八、單人創辦人被寫成優勢，卻沒有充分處理風險

Pitch 裡有一句：

一個人 + AI，完成一般團隊才能做的產品。

這確實很有記憶點。

但補助評審也可能立刻想到：

誰審教材？
誰負責資安？
誰做客服？
誰做行銷？
誰做財務核銷？
創辦人生病怎麼辦？
392 支 API 誰維護？

所以「一人完成很多」可以證明執行力，不能直接等於未來仍應該一人做完。

正確敘事應該是：

創辦人已用 AI 驗證高效率開發能力；補助將用於補足內容審訂、AI 品質評測、資安與市場驗證等單人無法長期承擔的專業缺口。

這樣補助的必要性才成立。

因為評審不是來看你做了多少。

他要看：

給你錢後，會新增什麼公共價值與可驗證成果？
